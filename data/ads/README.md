# Ads data

The local, **git-ignored** store for Meta ad campaigns run through `/ps:ads`. It is the
long-term memory of what was tested and what won or lost, so every new campaign starts
from evidence instead of a blank page.

- **`/ps:ads new`** writes a campaign record and one tracker record per ad (`verdict: testing`),
  and keeps a copy of every asset.
- **`/ps:ads creative`** writes asset copies (and tracker records when it attaches ads).
- **`/ps:ads review`** appends a metrics snapshot to every ad, sets verdicts
  (`winner` / `loser` / `fatigued` / `inconclusive`), logs the review on the campaign, and
  regenerates `learnings.md`.

## Why this is NOT version-controlled

The psstack repo is **public**. This store holds a business's ad spend, cost per lead,
Meta account/campaign IDs, landing URLs, and unreleased creative. None of that belongs in a
public git history. So everything here except this `README.md` and the two schemas is
listed in `.gitignore` (decided 2026-09-13).

**Consequence: it's local-only and not backed up by git.** Back it up yourself (Time
Machine, an encrypted personal backup) if you want durability. Meta keeps the raw metrics,
but the tags, verdicts, asset copies, and learnings exist only here.

It lives at `data/ads/` at the psstack repo root (not inside the plugin) so a marketplace
reinstall of `ps` never wipes it, matching `data/social/` and `data/sdr/`.

## Location resolution

Resolve as `data/ads/` at the root of the psstack repo. If running as an installed plugin
and the checkout isn't found: `$PSSTACK_DIR/data/ads`, then `~/Projects/psstack/data/ads`,
then ask Pedro. Confirm the absolute path before writing.

## Files

| File | Tracked | What it holds |
| :--- | :--- | :--- |
| `README.md` | yes | This file. |
| `campaigns.schema.json` | yes | JSON Schema for one `campaigns.jsonl` record. |
| `creatives.schema.json` | yes | JSON Schema for one `creatives.jsonl` record. |
| `campaigns.jsonl` | **no** | One JSON object per campaign: brief, Meta IDs, status, ad ids, review log. |
| `creatives.jsonl` | **no** | **The winners/losers tracker.** One JSON object per ad: name, asset copies + links, copy, analysis tags, launch context, append-only metric snapshots, verdict + history. Never delete records. |
| `assets/<brand>/` | **no** | Kept copy of every creative file, named `<ad_name>__<preset>.<ext>`. |
| `learnings.md` | **no** | Derived per-brand scorecard regenerated by `review` from `creatives.jsonl`. |

## Conventions

- **Append, don't rewrite.** `snapshots[]`, `verdict_history[]`, and campaign `reviews[]` are
  append-only. The top-level `verdict` is the current state; history explains how it got there.
- **Money in account currency units**, not cents (Meta's API uses cents; convert on write).
- **Percentages as percents** (`1.24` means 1.24%).
- **Dedupe** tracker records by `meta.ad_id` (fallback: `id`).
- **Unknown = `null`**, never a guess. `extra` holds anything the schema doesn't cover yet.
- Validate each record against its schema; one record per line.
